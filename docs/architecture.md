## 1. Обзор проекта и цели

Проект представляет собой MVP аналитической системы для ставок на спорт с фокусом на русскоязычный рынок букмекеров. Основная цель — создание воспроизводимого, научно обоснованного пайплайна, который:

- Собирает котировки с нескольких источников (API и веб-скрапинг)
- Нормализует и хранит данные в структурированном виде
- Тестирует гипотезы на исторических данных без утечки информации из будущего
- Генерирует сигналы с явной оценкой ожидаемого края (edge)
- Ведёт бумажный журнал для валидации перед реальными ставками
- Доставляет сигналы через Telegram-бота

**Не является:** системой автоматического размещения ставок. Все решения о реальных ставках принимаются пользователем вручную.

### Ключевые принципы

1. **Воспроизводимость** — каждый бэктест привязан к версии стратегии и хэшу датасета.
2. **Отсутствие утечки данных** — строгое соблюдение временно́й границы при мёрже данных.
3. **Прозрачность** — каждый сигнал содержит объяснение и метрики уверенности.
4. **Постепенное развёртывание** — paper trading → live signals → (опционально) автоматизация.

## 2. Системные компоненты

### 2.1 Сбор данных (Data Ingestion)

Отвечает за загрузку котировок, результатов матчей и новостей об игроках из внешних источников.

- Поллинг API по расписанию (cron / APScheduler)
- Сохранение сырых ответов в неизменяемом виде (raw layer)
- Идентификация дублей и управление лимитами запросов

### 2.2 Нормализация (Normalization / QC)

Преобразует разнородные форматы источников в единую схему.

- Дедупликация событий по `normalized_event_id`
- Конвертация форматов котировок (десятичные, дробные, американские)
- Проверка качества данных (QC-скоры)
- Timestamp-aware мёрж с учётом временны́х зон

### 2.3 Бэктестинг (Backtesting)

Walk-forward тестирование стратегий на исторических данных.

- Строгое разделение train/test окон
- Расчёт метрик: ROI, Yield, CLV, Max Drawdown
- Привязка к версии стратегии и хэшу датасета
- Генерация отчётов по каждому прогону

### 2.4 Генерация сигналов (Signal Engine)

Применяет стратегии к актуальным данным и производит сигналы.

- Расчёт fair odds через devigging
- Оценка edge = (entry_odds / fair_odds - 1)
- Фильтрация по порогам уверенности и минимальному edge
- Запись в `signal_record` со статусом `paper`

### 2.5 Репортинг (Reporting)

Формирование сводных отчётов по результатам бэктестов и paper trading.

- HTML/CSV/Parquet экспорт
- Дашборды через Jupyter Notebook (опционально)
- Ежедневная сводка P&L по бумажному журналу

### 2.6 Telegram-интеграция

Доставка сигналов и отчётов конечному пользователю.

- Bot API (python-telegram-bot)
- Команды: `/signals`, `/pnl`, `/backtest_summary`
- Уведомления при появлении нового сигнала выше порогового edge

## 6. Агенты системы

Каждый агент — отдельный Python-модуль с чётко определёнными входами и выходами.

### 6.1 `repo-scout`
**Роль:** Исследование open source репозиториев для повторного использования.  
**Вход:** Список поисковых запросов и критериев  
**Выход:** `docs/open_source_landscape.md` с оценками пригодности

### 6.2 `odds-ingest`
**Роль:** Сбор котировок из внешних API по расписанию.  
**Вход:** Конфиг источников, список спортов и лиг  
**Выход:** `data/raw/odds/YYYY-MM-DD/snapshot_*.parquet`

### 6.3 `illness-news`
**Роль:** Мониторинг новостей о травмах и дисквалификациях игроков.  
**Вход:** Список команд/игроков, RSS-фиды, API новостей  
**Выход:** `data/raw/injuries/injury_events.parquet`

### 6.4 `qc-normalizer`
**Роль:** Валидация, нормализация и дедупликация сырых данных.  
**Вход:** `data/raw/`  
**Выход:** `data/staging/normalized_odds.parquet`, `data/staging/injury_event.parquet`

### 6.5 `backtester`
**Роль:** Walk-forward бэктест стратегий на исторических данных.  
**Вход:** Стратегия (H001..H005), staging данные, конфиг окна  
**Выход:** `data/core/backtest_trade.parquet`, метрики в БД

### 6.6 `modeler`
**Роль:** Построение вероятностных моделей (Dixon-Coles, Poisson и т.д.).  
**Вход:** `data/core/result_core.parquet`, исторические котировки  
**Выход:** Калиброванные вероятности в `data/core/`

### 6.7 `signal-engine`
**Роль:** Генерация торговых сигналов на основе актуальных котировок.  
**Вход:** `data/staging/normalized_odds`, модели, пороги edge  
**Выход:** `data/core/signal_record.parquet`

### 6.8 `reporter`
**Роль:** Формирование отчётов по бэктестам и paper trading.  
**Вход:** `data/core/`, метрики  
**Выход:** `data/reports/` (HTML, CSV)

### 6.9 `telegram-bot`
**Роль:** Доставка сигналов и отчётов пользователю.  
**Вход:** `data/core/signal_record`, конфиг бота  
**Выход:** Telegram-сообщения

## 7. API-интеграции

### 7.1 The Odds API
- **URL:** https://api.the-odds-api.com
- **Данные:** Pre-match и live котировки по 40+ спортам
- **Формат:** JSON REST API
- **Лимиты:** Зависят от тарифного плана (500–100 000 запросов/месяц)
- **Ключевые рынки:** h2h, spreads, totals
- **Хранение:** `raw_odds_snapshot` → `normalized_odds`

### 7.2 Football-Data.co.uk
- **URL:** https://www.football-data.co.uk/data.php
- **Данные:** Исторические результаты и котировки на закрытие (closing odds)
- **Формат:** CSV файлы по лигам
- **Лимиты:** Бесплатно, без ключа
- **Покрытие:** 30+ европейских лиг, данные с 1990-х
- **Использование:** Базис для бэктестов, источник closing odds

### 7.3 SportsDataIO
- **URL:** https://sportsdata.io
- **Данные:** Составы команд, статистика игроков, расписания
- **Формат:** JSON REST API
- **Лимиты:** По тарифному плану
- **Ключевые поля:** Статусы игроков (injury reports)

### 7.4 Betfair Historical Data
- **URL:** https://historicdata.betfair.com
- **Данные:** Тик-данные торгов на бирже (Betfair Exchange)
- **Формат:** Bz2-архивы с JSON потоками
- **Использование:** Построение reference closing line (sharp market proxy)
- **Парсинг:** `betfairlightweight` библиотека

## 8. Российские букмекеры

Система ориентирована на мониторинг котировок следующих букмекеров:

| Букмекер | Идентификатор | Тип | Примечания |
|----------|--------------|-----|------------|
| Fonbet | `fonbet` | Легальный РФ | Крупнейший по обороту, собственный API |
| Winline | `winline` | Легальный РФ | Высокие лимиты на футбол |
| BetBoom | `betboom` | Легальный РФ | Бывший BetCity, активен в live |
| OlimpBet | `olimpbet` | Легальный РФ | Широкая роспись на киберспорт |

**Особенности работы с российскими букмекерами:**
- Котировки доступны преимущественно через веб-скрапинг (официальных API нет)
- Необходим учёт временны́х зон (MSK = UTC+3)
- Лимиты ставок существенно ниже, чем у европейских бирж
- Верификация аккаунтов обязательна (ЦУПИС)

## 9. Слои данных

```
RAW      → Исходные данные «как есть» из API/скрапинга. Только добавление.
             Никогда не изменять, никогда не удалять.

STAGING  → Нормализованные, прошедшие QC данные. Единая схема.
             Дубли устранены. Типы проверены. QC-скор присвоен.

CORE     → Агрегированные данные, обогащённые бизнес-логикой.
             Бэктесты, сигналы, бумажный журнал.

REPORTS  → Готовые к потреблению артефакты.
             HTML-отчёты, CSV-экспорт, Telegram-сообщения.
```

Переход между слоями только вперёд. Обратное редактирование запрещено.

## 10. Безопасность и правовое соответствие

### 10.1 Хранение секретов
- API-ключи только в переменных окружения (`.env` файл, не в репозитории)
- `.env` добавлен в `.gitignore`
- Для production — использование секрет-менеджера (Vault, AWS Secrets Manager)

### 10.2 Ограничения скрапинга
- Соблюдение `robots.txt` всех сайтов
- Минимальный rate limit между запросами (≥ 2 сек)
- User-Agent идентифицирует систему и контактный email

### 10.3 Правовые замечания
- Система предназначена исключительно для аналитики и исследований
- Не осуществляет автоматическое размещение ставок
- Пользователь самостоятельно несёт ответственность за соблюдение законодательства страны проживания
- Анализ данных букмекеров производится в образовательных целях

### 10.4 GDPR / ФЗ-152
- Персональные данные игроков (статусы травм) получены из публичных источников
- Личная информация пользователей системы не собирается и не хранится
